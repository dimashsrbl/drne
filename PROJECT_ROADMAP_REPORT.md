# Отчёт / дорожная карта проекта (Drone + Raspberry Pi + INAV)

Документ фиксирует последовательность работ: **что делаем** и **зачем** (какую бизнес‑цель закрывает шаг).

## 1) Разработка базового ПО (backend + frontend)
- **Что делаем**
  - Реализуем API управления дроном: команды, телеметрия, миссии, навигация.
  - Реализуем веб‑интерфейс для запуска команд и сборки миссий.
- **Зачем**
  - Создать единый “пульт управления” и базовую платформу, к которой дальше подключаются реальные устройства и сенсоры.

## 2) Проверка логики без железа (симуляция/стенд)
- **Что делаем**
  - Запускаем backend и проверяем, что эндпоинты работают (HTTP 200, корректные ошибки, валидация).
  - Прогоняем сценарии миссий в безопасном окружении (симуляция/адаптер), без риска для оборудования.
- **Зачем**
  - Рано подтвердить, что логика миссий и API работают, до подключения реального дрона.
  - Сократить время отладки на железе.

## 3) Подготовка Raspberry Pi как бортового компьютера
- **Что делаем**
  - Разворачиваем backend на Raspberry Pi.
  - Настраиваем автозапуск и стабильную работу сервиса.
  - Проверяем, что API доступен по сети.
- **Зачем**
  - Сделать Raspberry Pi “центром управления” на борту, который будет принимать команды с веб‑фронта и передавать их контроллеру.

## 4) Интеграция Raspberry Pi ↔ полётный контроллер (INAV)
- **Что делаем**
  - Настраиваем коммуникацию Raspberry Pi с полётным контроллером.
  - Проверяем, что телеметрия и канал управления доступны со стороны backend.
- **Зачем**
  - Критический этап: без устойчивого канала связи невозможно безопасно запускать миссии и получать состояние дрона.

## 5) Тестирование миссий на реальном дроне
- **Что делаем**
  - Запускаем короткие тестовые сценарии: подготовка → старт → ожидание → завершение.
  - Дальше — миссии на несколько точек и возврат (RTL/посадка по сценарию).
  - Фиксируем результаты и обновляем сценарии/ограничения безопасности.
- **Зачем**
  - Подтвердить, что вся цепочка “Frontend → Backend → Контроллер → Дрон” выполняет задачу автономного полёта по миссии.

## 6) Подключение камеры к Raspberry Pi
- **Что делаем**
  - Подключаем камеру и получаем видеопоток/кадры в backend.
  - Добавляем вывод статуса и визуализацию на фронте.
- **Зачем**
  - Подготовить основу для компьютерного зрения и последующих функций “видит‑понимает‑реагирует”.

## 7) Тестирование YOLO (детекция) и трекинга
- **Что делаем**
  - Запускаем детекцию объектов и трекинг на Raspberry Pi.
  - Замеряем производительность и стабильность, дорабатываем режимы запуска.
- **Зачем**
  - Подготовить “vision‑слой” как будущий источник событий (объекты/опасности), который можно использовать в логике полёта и UI.

## 8) Интеграционный тест “миссии + телеметрия + камера”
- **Что делаем**
  - Запускаем миссии параллельно с видеопотоком и обработкой кадров.
  - Проверяем, что система стабильна, а интерфейс корректно отображает состояние.
- **Зачем**
  - Доказать готовность к реальной эксплуатации: управление и “восприятие” работают одновременно.

## 9) Тиражирование на следующий дрон (например, VTOL)
- **Что делаем**
  - Переносим backend/настройки/процессы на новую платформу.
  - Повторяем этапы интеграции и тестов, адаптируем сценарии под особенности новой конфигурации.
- **Зачем**
  - Масштабировать решение на разные аппараты без переписывания системы с нуля.

## Текущий статус
- **Сейчас выполняется**: этап 4 — интеграция Raspberry Pi ↔ INAV (проверка устойчивой связи и телеметрии).
- **Следующее после успешной интеграции**: этап 5 — практический прогон миссий на реальном дроне.
